# Сводка для support-отдела

Скрипт сверяет операции из CRM с сообщениями из рабочих чатов и собирает список дел: что требует вмешательства, что подтверждено в CRM, что известно только из переписки, что проверить и что делать дальше.

## Как устроено

1. **Правила** читают CRM и определяют срочность. ИИ в этом не участвует.
2. **ИИ** по инструкции из `prompt.md` разбирает сообщения: что утверждает автор, как это соотносится с CRM, что проверить.
3. **Сборка** выводит сводку: срочные случаи сверху, по каждому отдельно факты CRM и слова из переписки.

| Операция | Что смотрим в CRM | Срок | Результат |
|---|---|---|---|
| Оформление сотрудника | документы не получены | дата первого выхода | срок прошёл / сегодня / завтра; раньше — без действий |
| Увольнение сотрудника | нет подтверждения руководителя | последний рабочий день | то же |
| Поставка карт | статус не «Принято» | время доставки | срок прошёл, как только время наступило |
| Любая | по CRM порядок, но ИИ нашёл в сообщении проблему | — | «расхождение с CRM», в группу «сегодня» |
| Любая | есть сообщения, а ИИ не ответил или ответил не по схеме | — | «прочитать вручную» |

Три ограничения для ИИ зашиты в код:

- случай, который пометили правила, ИИ не может ни опустить, ни закрыть;
- ИИ может только поднять случай, по которому в CRM всё в порядке;
- если ИИ недоступен или ответил не по схеме, сводка всё равно выходит, а сообщения приводятся дословно с пометкой «прочитать вручную».

Короткие сообщения (до 120 знаков) в сводке цитируются дословно, длинные — в пересказе модели.

## Запуск

Нужен Python 3.9+, зависимостей нет.

```
python svodka.py cases.json --no-llm
```

С моделью (PowerShell):

```
$env:LLM_PROVIDER = "openai"        # любой OpenAI-совместимый сервис; либо anthropic
$env:LLM_API_KEY  = "<ключ>"
$env:LLM_MODEL    = "<название модели>"
python svodka.py cases.json -o out/svodka.md --log out/log.jsonl
```

`LLM_BASE_URL` задаёт адрес сервиса, если он не стандартный (другой провайдер, локальная модель). `--log` дописывает сырые ответы модели в файл.

Проверки без обращения к модели:

```
python -m unittest -v
```

## Файлы

| Файл | Что внутри |
|---|---|
| `prompt.md` | инструкция для ИИ |
| `svodka.py` | правила, запрос к модели, сборка сводки |
| `cases.json` | четыре случая из задания |
| `cases_extra.json` | восемь новых случаев для проверки |
| `test_svodka.py` | проверки правил, сборки и устойчивости к плохим ответам модели |

## Допущения

- Формат входа (`cases.json`) придуман под задание: в CRM есть дата первого выхода, отметка о документах, последний рабочий день, отметка о подтверждении руководителя, срок и статус доставки. Реальную выгрузку нужно будет привести к этим полям.
- Сообщения уже привязаны к операциям. В жизни эту привязку надо строить отдельно.
- «Понедельник, 10:00» из задания — это 16.11.2026 10:00. Если поля `now` нет, берётся текущее время.
